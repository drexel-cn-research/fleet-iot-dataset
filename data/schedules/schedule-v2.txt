# Injection schedule v2 (Run 8): population context. Committed before the run.
# Times are explicit (run with SPACING=0). Conditions are 20 minutes apart so
# the class-level change rate (rho) of one condition never overlaps the next;
# a beacon lasts 10 minutes. Home A = RPI5-IoT (main LAN), home B = RPI4-IoT
# (routed subnet).
#
#   isolated       one device of a class changes; its class peers stay clean
#   within-home    two devices of one model in one home change together
#   cross-home     the same model in both homes changes together
#   spreading      a class changes one device at a time, across both homes
#
# Beacon conditions compare isolated vs. cross-home on cameras (camera class:
# hik-cam-1/2, wyze-cam-1/2). New-destination conditions compare isolated vs.
# within-home on speakers (nest-mini-1/2, echo-dot, sonos-one) and isolated vs.
# spreading on plugs (tuya-plug-1/2, kasa-plug-1/2, shelly-plug).
#
# Slots (no inline comments below: inject-schedule.sh reads four fields):
#      0 min  hik-cam-1    isolated, camera, home B
#     20 min  wyze-cam-1   cross-home, camera (same model), home B
#     22 min  wyze-cam-2   ... and home A, 2 min later
#     40 min  echo-dot     isolated, speaker, home A
#     60 min  nest-mini-1  within-home, speaker (same model), home A
#     62 min  nest-mini-2  ... second device, 2 min later
#     80 min  kasa-plug-1  isolated, plug, home B
#    100 min  tuya-plug-1  spreading, plug: home B
#    105 min  kasa-plug-2  ... home B, 5 min later
#    110 min  shelly-plug  ... home A, 10 min later
#
